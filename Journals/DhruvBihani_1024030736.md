## Work Completed

During the first week, our team finalized the project idea for the semester project. We decided to extend our Resource Booking System, which was previously developed as a DBMS project using Oracle Database, into a complete web-based software application.

The main objective of the new project is to provide a centralized system for managing campus resources such as classrooms, laboratories, seminar halls, and other shared facilities. The system will allow users to check resource availability and submit booking requests, while administrators will be responsible for managing resources and handling booking requests.

My primary contribution during this week was to review and analyze the existing Oracle database implementation from the previous DBMS project. I examined the database schema, tables, relationships, constraints, and the existing booking-related logic.

The current database contains the main entities required for the system, including departments, users, resources, slots, bookings, and resource logs. I also reviewed the existing database functionality such as booking creation, slot availability checking, booking cancellation, status updates, triggers for maintaining logs, and resource usage reporting.

Based on this analysis, I identified that the existing database can serve as a strong foundation for the Software Engineering project. However, the project will require additional application-level functionality, including user authentication, a web-based user interface, role-based access, dashboards, improved booking workflows, and proper testing.

I also discussed the project scope with my teammate. We decided to keep the core scope manageable for a two-member team. The initial implementation will focus on authentication, resource management, slot availability, booking requests, conflict prevention, booking approval or rejection, and booking history. More advanced features such as AI-based prediction, QR verification, and mobile application support will be treated as future enhancements rather than core requirements.

## Key Observations

The previous DBMS project mainly focused on database design and SQL operations. The current semester project will extend this work into a complete software system.

The major additions planned for the new project are:

- Web-based user interface
- Java-based application logic
- User authentication
- Role-based access control
- Resource management
- Booking workflow
- Booking conflict validation
- User and administrator dashboards
- Testing and validation
- Software engineering documentation

## Learning and Reflection

This week's work helped me understand the importance of analyzing an existing system before extending it. Instead of rebuilding the project from scratch, we can reuse the existing database structure and focus on developing the missing software layers.

I also understood that defining a realistic project scope is important, especially because the team consists of two members and the project has to be completed within one semester. Therefore, we decided to prioritize a stable and functional core system before considering additional features.
